# تصميم مشروع مختبر معلومات الزيارة

التاريخ: 2026-10-24

الحالة: تصميم اعتمده المستخدم ونُفّذ، مع التحديثات المعتمدة أدناه.

## المطلوب

تكليف دراسي للأمن السيبراني: إنشاء روابط من لوحة تحكم، ثم حفظ معلومات الزيارة والجهاز المتاحة للويب تلقائيًا عند فتح الرابط، وعرضها في لوحة التحكم. لا يظهر زر موافقة ولا يتوقف الحفظ على موافقة الزائر، وفق تصحيح المستخدم.

## المكان والتقنية

- المجلد المقترح: `F:\my-software-projects\JavaScript\device-info-lab`.
- JavaScript بوحدات ES، وCloudflare Worker، وWrangler، وقاعدة D1 جديدة باسم `device-info-lab-db`.
- لوحة عربية متجاوبة تدعم RTL، وملفات HTML/CSS/JavaScript يستضيفها Worker نفسه عبر Static Assets.
- اتباع تنظيم `soor-api`: Controllers وServices وRepositories وقواعد Base صغيرة، ومفاتيح JSON بصيغة camelCase، وثوابت ورسائل مركزية.
- قاعدة جديدة مستقلة: لا يُنسخ ربط `soor-db` ولا تُستخدم قواعد أو مفاتيح أو نطاقات المشروع المرجعي.

## الأساليب المدروسة

1. Worker واحد مع Static Assets وD1: أبسط للتشغيل والتسليم الدراسي، والواجهة والـAPI على النطاق نفسه. هذا هو المقترح لأنه يطابق المنصة التي طلبها المستخدم.
2. واجهة React منفصلة مع API Worker: مناسبة إذا توسعت الواجهة كثيرًا، لكنها تضيف بناءً واعتماديات ونشرًا إضافيًا لا يحتاجها التكليف الحالي.

تفاصيل الواجهة واسم المجلد وسياسة الاحتفاظ أدناه مقترحات تنفيذية، وليست اختيارات صرّح بها المستخدم.

## سلوك الرابط

1. ينشئ المسؤول رابطًا باسم توضيحي ومدة صلاحية.
2. ينتج مسار غير قابل للتخمين مثل `/v/<randomToken>`.
3. طلب GET صالح يحفظ سجل الزيارة الأساسي في D1 قبل إرجاع صفحة الزيارة.
4. تعرض الصفحة بوضوح أنها تجربة دراسية لمعلومات المتصفح، دون مطالبة بالموافقة أو تفاعل قبل التسجيل.
5. JavaScript يرسل معلومات الشاشة واللغة والمنطقة الزمنية تلقائيًا إلى نقطة إثراء مرتبطة بسجل الزيارة نفسه.
6. يُمنع إنشاء سجل إضافي عند الإثراء. الطلب الموقّع قصير الصلاحية ومربوط بالرابط والزيارة، والحقول القابلة للتحديث محددة.
7. طلبات HEAD ومعاينات prefetch المعروفة لا تُسجّل كزيارة بشرية؛ يُشار إلى الروبوتات المعروفة ولا يُدّعى كشف جميع المعاينات أو البشر.
8. الرابط المتوقف أو المنتهي لا يقبل زيارات أو إثراءً جديدًا. لا توجد إعادة توجيه مخفية.

## البيانات

من الطلب الموثوق عند الحافة: وقت الزيارة، IP العام من `CF-Connecting-IP`، إصدار IP، User-Agent، اللغة، الدولة والمدينة والمنطقة التقريبية حسب IP، ASN واسم مزود الشبكة، نسخة HTTP وTLS إن توافرت.

من المتصفح تلقائيًا إن كانت الخاصية متاحة: اللغة، المنطقة الزمنية، أبعاد الشاشة ونافذة العرض، نسبة البكسل، دعم اللمس، ونوع النظام والمتصفح المستنتجان من بياناتهما الاعتيادية. تعرض القيم غير المتاحة على أنها غير متاحة.

معلومات المتصفح قابلة للتعديل أو التزوير؛ لا تُعامل كإثبات لهوية الشخص أو طراز جهازه. بيانات IP تقريبية وقد تعبّر عن VPN أو شبكة وسيطة. لا تُجمع كلمات مرور أو ملفات أو جهات اتصال أو معرفات عتاد، ولا يُطلب GPS أو كاميرا أو ميكروفون، ولا تستخدم بصمات Canvas أو WebGL.

## لوحة التحكم

- تسجيل دخول بمفتاح مسؤول محفوظ في Cloudflare Secrets؛ لا توجد كلمة مرور افتراضية في المصدر.
- ملخص عدد الروابط والزيارات والزيارات الحديثة.
- إنشاء رابط ونسخه، وتحديد صلاحيته، وتعطيله أو تفعيله، وحذفه مع بياناته بعد تأكيد المسؤول.
- قائمة زيارات مع بحث وترقيم صفحات وتصفية حسب الرابط.
- عرض تفاصيل الزيارة مع فصل مصدر كل قيمة: الحافة أو المتصفح.
- تصدير JSON للنتائج المصرّح بعرضها.
- حالات تحميل وفشل وفراغ واضحة، وإدارة انتهاء جلسة المسؤول.

## REST API المقترح

| الطريقة | المسار | الغرض |
| --- | --- | --- |
| GET | `/api/health` | حالة الخدمة دون بيانات حساسة |
| POST | `/api/auth/login` | بدء جلسة المسؤول |
| POST | `/api/auth/logout` | إنهاء الجلسة |
| GET | `/api/auth/session` | حالة الجلسة |
| GET / POST | `/api/links` | عرض الروابط أو إنشاء رابط |
| PATCH / DELETE | `/api/links/:id` | تحديث رابط أو حذفه |
| GET | `/api/stats` | إحصاءات لوحة التحكم |
| GET | `/api/visits` | زيارات ببحث وتصفية وترقيم صفحات |
| GET | `/api/visits/:id` | تفاصيل زيارة |
| GET | `/api/export` | تنزيل JSON |
| GET | `/v/:token` | تسجيل الزيارة وعرض الصفحة |
| POST | `/api/visits/enrich` | إثراء زيارة بتفويض قصير الصلاحية |

كل مسارات الإدارة محمية؛ لا يكشف امتلاك رابط الزيارة سجلاته أو إحصاءاته.

## D1 وفصل المسؤوليات

- `links`: معرّف ورمز عشوائي فريد وعنوان ووقت إنشاء وانتهاء وحالة التفعيل.
- `visits`: معرّف ورابط مرتبط ووقت الزيارة وحقول الحافة والمتصفح ووقت انتهاء الاحتفاظ.
- `adminSessions`: تجزئة رمز جلسة المسؤول ووقت انتهائها؛ لا تُحفظ رموز الجلسات بصورتها الخام.
- فهارس للرموز وأوقات الزيارات والرابط وتاريخ انتهاء الاحتفاظ.
- استعلامات مربوطة المعاملات. عمليات حذف الروابط وبياناتها متسقة ذريًا ضمن D1.
- Controllers للتحقق من الطلب، Services للسلوك، Repositories للاستعلامات، ومجمع واحد لبيانات الحافة وأداة واحدة لتحليل User-Agent.

## ضوابط التنفيذ

- رموز روابط وجلسات باستخدام Web Crypto.
- Cookie جلسة HttpOnly وSecure في الإنتاج وSameSite، مع فحص Origin للكتابات الإدارية، ودون CORS مفتوح للإدارة.
- حماية من XSS باستخدام textContent وترويسات CSP، وعدم حقن مدخلات المسؤول أو User-Agent في HTML.
- حدود لحجم الطلب والحقول والترقيم والتصدير، وعدم تخزين بيانات زيارات أو أسرار في سجلات console.
- افتراضي مقترح للاحتفاظ: 30 يومًا، مع مهمة مجدولة لحذف السجلات المنتهية فقط.
- تحدّ محاولات تسجيل الدخول والإثراء المتكرر، ولا يعتمد الحد على ذاكرة Worker المحلية وحدها.
- إعدادات محلية نموذجية بلا أسرار حقيقية، وREADME عربي لتهيئة D1 وSecrets والتشغيل والنشر.

## التحقق والتسليم

- اختبار مسارات الإدارة دون جلسة، وإنشاء الرابط، والتسجيل التلقائي، والإثراء الصحيح، ورفض التفويض المزوّر أو المنتهي، وتعطيل الرابط، والتحقق من مدخلات SQL وHTML.
- التحقق من إنشاء schema واستخدام فهارسه وعمل حذف البيانات المرتبطة على SQLite/D1 محلي.
- مراجعة الواجهة بالعربية على الحاسوب والهاتف عند السماح بتشغيلها.
- تبقى قاعدة D1 السحابية ومعرّفها وSecrets والنشر خطوات تشغيلية مستقلة عن كتابة الملفات.
- احترام توجيه المستخدم بعدم التشغيل أو البناء دون إذن صريح. لا تُدّعى نتائج تشغيل أو اختبارات لم تُنفّذ.

## تحديثات المستخدم أثناء التنفيذ

- اسم الواجهة فقط: مريم لينك. يبقى المجلد device-info-lab وقاعدة البيانات device-info-lab-db.
- روابط الزيارة على https://info.aslyemen.com، والإدارة على https://devics-panel.aslyemen.com.
- أُجيز التشغيل والاختبار والنشر والدفع إلى مستودع عام تحت connecttag والترحيل صراحةً بعد اعتماد التنفيذ. يحل ذلك محل قيد عدم التشغيل السابق لهذا المشروع.
- إضافة ستة قوالب: ترحيب، معلومات الجهاز الحالي، ترويج لشركة، 404 فعلية، دخول تدريبي، وصفحة نصية مخصصة.
- لا توجد لوحة حساب للزائر. قالب معلومات الجهاز يعرض زيارته الحالية مباشرةً؛ بقية النتائج تحفظ للإدارة.
- نموذج التدريب لخدمة خيالية، ويقبل حساب المختبر العام المحدد فقط. لا يوجد انتحال لخدمة خارجية أو حفظ كلمات مرور حقيقية.
- توسيع البيانات إلى المؤشرات الاعتيادية التي يتيحها المتصفح والترويسات المسموح بها، دون تجاوز قيود المتصفح أو طلب صلاحيات حساسة.
- تفاصيل الحماية والـAPI النهائية موثقة في README وdocs/API.md. حد التصدير النهائي 250 سجلًا لحماية ذاكرة Worker بعد توسيع معلومات الزيارة.
